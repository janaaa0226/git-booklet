Setup (do once)

You need three things: Git installed, a free GitHub account (github.com), and ideally VS Code. Install Git from git-scm.com (on Windows, click Next through the installer). To open a terminal in VS Code, press Ctrl + `. A terminal is just a text box where you type instructions instead of clicking buttons.

Check Git is installed
git --version

You should see something like git version 2.45.0. If it says "not recognized", close and reopen VS Code, or reinstall Git.

Now tell Git who you are. Every checkpoint you save is stamped with this name.

Set your identity
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Use the same email as your GitHub account so your work is linked to your profile.

01What are Git and GitHub?

In simple words

Git is a tool on your computer that keeps track of changes to your project. Think of save points in a game. You work, save a checkpoint, keep working, and if something goes wrong you can go back. (Tools like this are called version control systems.)

GitHub is a website where you store Git projects online, share them and work with other people.

Git and GitHub are NOT the same thing. Git works without internet and without GitHub. GitHub is one place to keep a copy.
How they fit together
YOUR COMPUTER              GITHUB (online)
Project + Git   --push-->  Stored copy
                <--pull--

Why do I need it?

Without Git you end up with essay_final_v3_REAL.docx. With Git there is one file and a history of every version. It also lets several people work on one project without overwriting each other, and employers look at GitHub profiles.

Quick check: which one is a website?

GitHub. Git is the program on your computer.

02Your first repository

We will use one imaginary project all the way through. A repository (repo) is simply a project folder that Git is tracking.

Our project
MyProject/
├── Main.java
├── Student.java
└── README.md

In VS Code choose File → Open Folder and open MyProject, then open the terminal.

Step 1: turn on Git

Start tracking this folder
git init

In simple words: "Git, start tracking this project." Git creates a hidden folder called .git inside. That is where it stores all the history. Never edit or delete it by hand.

You should see: Initialized empty Git repository in .../MyProject/.git/

Step 2: ask what is happening

Check the project
git status

In simple words: "Git, what is going on right now?" You will use this constantly.

Example output
On branch main
No commits yet
Untracked files:
        Main.java
        Student.java
        README.md

Reading it: On branch main is the line of work you are on. Untracked means Git can see the files but is not saving their history yet.

fatal: not a git repository means the terminal is not inside your project. Run pwd (or cd on Windows) to see where you are, and use cd MyProject to move into it.

03The basic workflow

This is the loop you will repeat for as long as you use Git.

The loop
EDIT your file
   ↓
git status   →  "What changed?"
   ↓
git add      →  "Include these changes in my next checkpoint"
   ↓
git commit   →  "Save the checkpoint"
   ↓
git push     →  "Send my checkpoints to GitHub"
git add does NOT upload anything. git commit does NOT upload anything. Both happen only on your computer. Only git push sends work to GitHub.

Your files move through three places:

Three places
WORKING DIRECTORY   "What I changed"
   ↓ git add
STAGING AREA        "What I want in my next commit"
   ↓ git commit
COMMIT              "Saved checkpoint"
You might change five files but only want three in the checkpoint. Staging lets you choose. Think of packing a box before you seal and label it.

04Staging and commits

Step 3: make a change

Open Main.java, add a line that prints "Hello", and save it (Ctrl + S). Then check:

See the change
git status
Output
Changes not staged for commit:
        modified:   Main.java

Git noticed Main.java differs from the last saved version. "Not staged" means it is not in the next checkpoint yet.

Step 4: stage it

Stage one file
git add Main.java
Stage everything that changed
git add .

The dot means "everything in this folder". Run git status again and the wording changes to Changes to be committed. That is how you know it worked.

Step 5: commit

Save the checkpoint
git commit -m "Add hello message"

Breaking it down: commit saves the checkpoint. -m means "here comes my message". The text in quotes describes what you did.

Output
[main 3f2a9c1] Add hello message
 1 file changed, 1 insertion(+)

Good messages say what changed: Add login form, Fix crash when name is empty. Bad ones: stuff, asdf, final. Future you will read these.

nothing to commit, working tree clean is not an error. It means you have no new changes. Type -m as one piece with no spaces, and use straight quotes.
Quick check: you edited Main.java. What comes before committing?

git add. It tells Git which changes to include in the commit.

05GitHub, origin and push

So far everything is only on your computer. Now we put a copy on GitHub.

Step 6: create an empty repo on GitHub

On github.com click + → New repository.

  • Name: for example MyProject.
  • Public means anyone can see it. Private means only you (and people you invite).
  • Do not tick "Add a README", since your project already has files. Adding one here makes the two copies disagree.
  • .gitignore and license are optional. A license says how others may reuse your code.

Before you push: .gitignore

A file named .gitignore lists things Git should never track: generated files, editor settings, and secrets.

Example .gitignore
.env
*.class
.vscode/
node_modules/
Never commit passwords, API keys or private secrets. Once pushed, treat them as public.

Step 7: connect the two, and meet origin

Connect your project to GitHub
git remote add origin https://github.com/YOURNAME/MyProject.git

A remote is another copy of your repo stored somewhere else. origin is just the nickname Git uses for the GitHub copy, so you don't type the long URL every time.

Step 8: push

First push
git push -u origin main
git pushSend my commits
originto the GitHub copy
mainfrom my main branch
-uremember this choice, so next time git push is enough

You should see lines like Writing objects: 100% and branch 'main' set up to track 'origin/main'. Refresh your GitHub page and your files are there. A browser window may ask you to sign in to GitHub. That is normal.

Which GitHub repo am I connected to?
git remote -v

06Pull and clone

git pull

"Get the latest changes from GitHub onto my computer." Use it when a teammate changed the project, or you edited on another computer.

Update your copy
git pull

git clone

"Copy an existing GitHub repository onto my computer." Use it once, to start from a project that already exists. It downloads everything, history included, and already sets up origin for you.

Download a project
git clone https://github.com/USER/project.git
clone = first time, get a copy. pull = later, get new changes. push = send your changes up.

07Branches and pull requests

Imagine main is your safe, working version. You want to try a new feature without risking it. So you create a separate branch, work there, and when you're happy, merge it back into main.

Picture
main     ●───●───●───────────●  (merge)
                  \         /
feature            ●───●───●
The branch commands
git branch                  # list branches (* = you are here)
git switch -c my-feature    # create a branch and move onto it
git switch main             # move back to main
git merge my-feature        # bring my-feature INTO the branch you're on
git branch -d my-feature    # delete it once merged

While on my-feature, add, commit and push as usual. It won't touch main. Older tutorials use git checkout for switching. It does the same job, and switch is the newer, clearer command.

Pull requests

A pull request (PR) is a GitHub feature that asks: "I made changes on my branch. Can we review them and merge them?" Push your branch, then click Compare & pull request on GitHub, describe your change, let others review, and click Merge.

08Merge conflicts

Person A changes line 5 to "A". Person B changes the same line 5 to "B". When Git merges, it cannot decide which is right. That is a conflict. Your project is not destroyed. Git is asking you to decide.

Git marks the file:

What you'll see in the file
<<<<<<< HEAD
the version on your branch
=======
the version from the other branch
>>>>>>> my-feature

<<<<<<< starts your version. ======= separates the two. >>>>>>> ends the other version. (HEAD means "where you are right now".)

  1. Open the file and decide what the final text should be.
  2. Delete all three marker lines, and keep only the text you want.
  3. Save the file.
  4. git add filename
  5. git commit (Git offers a default message; accept it).

VS Code shows buttons above each conflict: Accept Current, Accept Incoming, Accept Both. They do the same editing for you.

09Undoing mistakes

Almost everything committed in Git can be recovered. Start with the safe options.

SituationWhat to do
Changed a file, want the old version back (not committed)git restore file. This throws away your unsaved edits for good.
Staged something by accidentgit restore --staged file. Your edits stay.
Typo in the last commit messagegit commit --amend -m "New message" (only if not pushed yet)
Made a commit I don't likegit revert COMMIT_ID adds a new commit that cancels it out. History stays intact.
Pushed something wrongUse git revert, then push. Changing pushed history affects everyone.

Find a commit ID with git log --oneline.

git reset --hard deletes all uncommitted work permanently. git push --force overwrites GitHub's history and can erase teammates' work. Don't use either until you fully understand them, and ask someone first.

Sign-in and identity

Two different things get mixed up. Identity (user.name and user.email) is the name stamped on your commits. Sign-in is the account GitHub uses to allow you to push. They are related, but separate settings. To check where your project pushes to, run git remote -v. To see your identity, run git config user.name and git config user.email. GitHub no longer accepts your password in the terminal, so it opens a browser sign-in. That's why Git sometimes asks you to log in.

11Git error? Don't panic.

Errors almost always mean Git needs clarification. They do not mean your project is gone.

MessageMeaning and fix
not a git repositoryYour terminal is in the wrong folder. Use cd to enter the project, or run git init if you forgot.
remote origin already existsThe connection is already made. Check it with git remote -v. To change the address: git remote set-url origin NEW_URL.
nothing to commitNo new changes. Usually not a problem.
ahead of 'origin/main'You have commits GitHub doesn't. Run git push.
behind 'origin/main'GitHub has changes you don't. Run git pull.
push rejectedGitHub has newer work than you. Run git pull, fix any conflict, then git push. Don't force it.
Could not resolve hostNo connection to github.com. Check your internet, VPN or school network, then try again. Your commits are safe.
pathspec did not matchUsually a typo, like - m instead of -m, or a wrong file name.

What do I do if…

I changed code and want to save it:

Save and upload
git status
git add .
git commit -m "Describe what you did"
git push

I want to upload an existing project: git init, add and commit, create an empty repo on GitHub, then git remote add origin URL and git push -u origin main.

A friend changed the project: git pull. I want to try something risky: make a branch. Which GitHub repo is this? git remote -v.
