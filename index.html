1. What is Git?

Imagine writing an essay. You save essay.docx, then essay_final.docx, then essay_final_REALLY_final.docx. Messy, right?

Git is a tool that remembers every version of your files for you. It works like a video game with unlimited save points: you can go back to any earlier save, see what changed, and see who changed it.

Git is free, runs on your own computer, and works with any kind of text file (code, notes, web pages).

Why students should care

  • Safety: break something? Go back to a working version.
  • Teamwork: many people can work on one project without overwriting each other.
  • Portfolio: employers look at your GitHub profile.
  • Everyone uses it: it is standard in almost every software job.

2. Git vs GitHub

These are two different things, and beginners often mix them up.

Similar websites exist too, such as GitLab and Bitbucket. They all use Git underneath.

3. Setup

Step 1: Install Git

  • Windows: download from git-scm.com and click Next through the installer. You get "Git Bash", a terminal to type commands in.
  • Mac: open Terminal and type git --version. It offers to install if missing.
  • Linux: sudo apt install git

Check it worked:

git --version

Step 2: Tell Git who you are

Do this once. Your name is attached to every save you make.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Step 3: Make a GitHub account

Go to github.com, sign up, and use the same email as above. Choose a professional username, since it becomes your public profile.

4. Key ideas

Repository (repo)
A project folder that Git is watching, including its whole history.
Commit
A save point. A snapshot of your files with a short message like "Add login page".
Staging area
A waiting room. You pick which changes go into the next commit.
Branch
A separate line of work, so you can experiment without touching the main version.
Remote
A copy of your repo stored somewhere else, usually GitHub.

The three places your files live

Working folderwhere you edit files
Staging areachanges you chose to save
Repositorysaved commits (history)

Moving between them: git add moves changes to staging. git commit moves them into history.

5. Your first repo

Follow along in your terminal.

mkdir my-project      # make a folder
cd my-project         # go inside it
git init              # start tracking it

Create a file called hello.txt with any text, then:

git status            # what has changed?
git add hello.txt     # put it in staging
git commit -m "Add hello file"   # save it
git log --oneline     # see your history

That is the core loop. Edit, then status, add, commit, and repeat.

Tip: use git add . to stage every changed file at once. Write commit messages that say what you did: "Fix typo in header", not "stuff".

Ignoring files

Some files should never be tracked (passwords, temporary files). Create a file named .gitignore and list them, one per line:

.env
node_modules/
*.log

6. Branches

Think of a tree. The trunk is your stable project (usually called main). A branch is a side path where you try something new. If it works, you join it back to the trunk. If not, you throw it away.

git branch                  # list branches
git switch -c new-feature   # create and move to a new branch
# ...edit files, add, commit...
git switch main             # go back to main
git merge new-feature       # bring the changes into main
git branch -d new-feature   # delete the finished branch
Rule of thumb: never work directly on main in a team. Make a branch for each task.

7. Using GitHub

Send your project to GitHub

  1. On GitHub, click New repository, give it a name, and create it.
  2. Copy the URL GitHub shows you, then run:
git remote add origin https://github.com/YOU/my-project.git
git branch -M main
git push -u origin main

Push means upload your commits. After the first time, just type git push.

Get a project from GitHub

git clone https://github.com/USER/project.git

Clone downloads a full copy, history included.

Stay up to date

git pull      # download and merge new changes from GitHub
CommandDirection
git pushyour computer → GitHub
git pullGitHub → your computer
git cloneGitHub → new folder on your computer (first time)
Login: GitHub no longer accepts your account password on the command line. Use GitHub Desktop, the GitHub CLI (gh auth login), or a personal access token when asked.

8. Pull requests

A pull request (PR) says: "I made changes on my branch. Please review them and add them to the main project."

  1. Create a branch, commit your work, and git push -u origin your-branch.
  2. On GitHub, click the Compare & pull request button.
  3. Write a short title and description of what you changed.
  4. Teammates comment and approve.
  5. Click Merge pull request.

Contributing to someone else's project

Click Fork to copy their repo into your account. Clone your fork, make changes on a branch, push, then open a pull request to the original. This is how open-source works.

9. Merge conflicts

A conflict happens when two people change the same line. Git can't decide who is right, so it asks you. Don't panic, it is normal.

Git marks the file like this:

<<<<<<< HEAD
your version of the line
=======
their version of the line
>>>>>>> other-branch

To fix it:

  1. Open the file and decide what the final text should be.
  2. Delete the <<<<<<<, ======= and >>>>>>> lines.
  3. Run git add file.txt then git commit.

10. Undoing mistakes

ProblemFix
Staged the wrong filegit restore --staged file
Want to throw away edits to a filegit restore file (permanent!)
Typo in your last commit messagegit commit --amend -m "New message"
Undo a commit safely (keeps history)git revert COMMIT_ID
Want to see what changedgit diff
Careful: avoid git reset --hard and git push --force until you fully understand them. They can destroy work.

Daily routine

  1. git pull to get the latest.
  2. Make a branch and do your work.
  3. git add . then git commit -m "...", often.
  4. git push, then open a pull request.
